# 管理员服务（第 20 件）

更新：2026-11-02。代码已接通；本机尚未安装服务，也没有执行真实的管理员改动。普通后台继续运行在用户桌面会话，锁屏、通知和用户状态监听不搬到 SYSTEM。

## 程序与权限边界

`away-guard-admin.exe` 是按 Windows 用户 SID 独立注册的 LocalSystem 服务。后台通过 `ServiceElevated` 调用它；没有安装、部署目录不可信或认证失败时，回 `DENIED / core.NEEDS_ELEVATION`，其他普通权限功能继续使用。

它只提供固定操作：

- 读取和设置指定网卡的 IPv4 / IPv6 metric，分别保存原值及自动 metric 状态；恢复时恢复两种协议的精确原值。
- 读取和推迟 Windows 更新策略，每个周期最多 35 天，续期不能移动周期起点，周期后至少留一天不暂停；保留并恢复原始注册表类型和值。是否被 Windows 家庭版采纳仍需实机验收。
- 读取和关闭已枚举网卡的省电选项，按网卡 PNP 身份匹配；不接受脚本内容。
- 读取 `powercfg /requests`。
- 调整当前用户进程的优先级，最高到 high；冻结、解冻、结束进程均核对 PID 与创建时间。系统、安全软件和自身程序禁止操作；目标令牌必须未提升、完整性不高于中等级且不高于调用方，无法查询令牌时拒绝。
- 出口保护的固定防火墙请求，复用出口模块的严格参数验证与恢复规则。

不接受命令行、脚本、任意注册表路径或任意可执行文件作为管理员请求。WMI / powercfg 使用固定程序和固定操作；数据经参数或 JSON 标准输入传入。

私有命名管道只允许本机 SYSTEM 和指定用户连接，用户权限不含创建管道实例；服务还从系统读取客户端 SID、PID、映像路径，只认受保护安装目录里的后台。客户端反向核对 SCM 注册的 LocalSystem 服务 PID、映像路径和部署 ACL。协议单帧最多 64 KiB，未知操作、未知字段和越界参数拒绝。

路径认证要求整个部署路径没有可替换的祖先、重解析点或普通用户写入权限。普通用户自己拥有的源码目录不能当作管理员部署目录。同账号进程注入等硬隔离问题仍遵循架构文档的权限边界。

## 安装与卸载

安装是单独的、需要用户授权的操作，构建和测试不会安装服务，也不会自动弹 UAC。

先构建，确保这些文件位于同一目录：`away-guard-admin.exe`、`away-guard-daemon.exe`、`away-guard-launcher.exe`、`away-guard.exe`。同目录存在的 hook 和 relay 也会复制。

```powershell
cargo build --workspace
# 以下命令需要在获得用户授权后，在该用户的管理员终端里执行：
.\target\debug\away-guard-admin.exe install --directory '<管理员已准备的受保护本地目录>'
.\target\debug\away-guard-admin.exe show
```

安装必须显式提供 `--directory <绝对路径>`，不再内置本机目录，也不默认安装到 C 盘。其他机器可自行选择本地卷；本机按存储规则选择 D 盘。客户端从 SCM 注册的服务映像路径发现部署目录，不使用 `AWAY_GUARD_ADMIN_DIR`。

安装器不会改动已有祖先的权限。若现有祖先属于普通用户或可被替换，会拒绝安装；管理员需要事先准备受保护目录。新目录在创建时就带最终 ACL，避免先创建后收紧权限的窗口。

服务只认复制后的后台，安装后应从部署目录运行 launcher / daemon，并把原有自启指向新 launcher。安装器会打印路径，不擅自改已有自启。用户数据可继续用 `AWAY_GUARD_DATA_DIR` 指向既有数据目录。

```powershell
# 获得用户授权后，在管理员终端卸载：
.\target\debug\away-guard-admin.exe remove
```

卸载先等待服务恢复并停止，再注销服务；保留受保护的二进制、审计和恢复文件。重新安装前须先卸载；可复用属于同一用户的受保护目录，恢复文件不被覆盖。正在运行的旧后台需要先退出，才能替换其二进制。

## 恢复与验收

可逆操作先同步写入部署目录的 `recovery.json`，再改系统；临时文件经写穿透原子替换。后台的 SQLite 恢复日志仍保留，服务再维护一份独立备份。后台进程退出、更新期限到期、服务停止或服务重新启动时，按备份恢复。服务崩溃和报告错误退出都配置 SCM 重启。客户端提前断开不会结束监听；其他监听错误退出前也会尝试恢复。审计在 `audit.ndjson`，达到 5 MiB 后轮换，不记录 API 正文或凭据。

恢复逐项进行：失败项保留，后续项目继续恢复；启动后按 1、2、4…60 秒退避重试，不因单个网卡失效而永久起不来。旧恢复记录与当前后台的新记录分别保存，重试旧记录不撤销新操作；只有冲突的同一恢复目标受限，防火墙操作独立放行。`recovery.json` 无法解析时重命名保留为 `recovery.corrupt.*.json`，服务保留状态查询和独立防火墙操作，但拒绝依赖损坏恢复日志的新修改，不会把未知恢复数据覆盖成空状态。管理员需核对隔离文件并修复恢复记录，未解决前不要删除隔离标记。无法解析的内容不能承诺自动还原。

路径认证不能阻止同用户注入后台；此服务仍是授予该用户的有限系统能力，不是针对同账号恶意代码的隔离边界。管理员进程明确不在可操作范围。

已自动验证协议边界、身份拒绝、用户可写部署拒绝、恢复文件持久性、损坏隔离、恢复项目互不阻塞、过期 PID / 系统目标拒绝、服务缺失回退。真实的安装 / 卸载、管理员目标、家庭版更新策略、网卡省电、双栈 metric 和服务崩溃恢复，需要获得安装授权后在此机验收。

接口定义：`crates/proto/src/admin.rs`；客户端、服务和固定操作在 `crates/platform/src/windows/admin/`。
