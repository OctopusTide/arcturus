## 已知问题

- 保护 Claude Code 本身时，它启动的后台程序可能会随它退出一起结束。只保护后台程序本身（比如训练脚本）不受影响。原因见[架构文档](../ARCHITECTURE.md#任务保护模块)，还没修。
- 在同一个 Windows 账号下，它挡不住存心绕过的 agent。"agent 只能申请"是给守规矩的 agent 用的，不是安全隔离。
- `away-guard-hook install --apply` 只在隔离的配置目录里跑过，没在日常用的配置上跑过。原文件会先备份。
- 续跑时没人批权限，需要批准的操作会被拒绝，开始续跑时会通知。
- API 中转重发请求可能重复计费，所以默认不开。

## 验收结果

2026-11-02。真实 Claude Code 2.1.309，配置目录隔离，本机假 API，不花钱。断网是在本机模拟的，没有真的拔网线。

最近一次全量自动测试（2026-11-02）：334 过，0 失败，2 个忽略。

### 断网后接着跑

| 场景 | 结果 |
|---|---|
| 断网等待，恢复后接上同一个对话 | 2.8 秒接上，对话编号不变 |
| 受保护的 agent 断网退出，网恢复后续跑 | 续上，同一个对话 |
| 受保护的 agent 续跑后的新进程 | 新进程以同样的名称和内存上限受保护 |
| 受保护的 agent 断网退出，离开模式 | 任务结束后等满 60 秒仍是离开模式，取消续跑后才退出 |
| 窗口开着，分叉接着做 | 分叉写成文件，模型不变，原窗口还活着 |

### 续跑和原来跑得一样

| 原来的启动方式 | 续跑后写文件 |
|---|---|
| `--dangerously-skip-permissions` | 写成 |
| `--permission-mode acceptEdits` | 写成 |
| 默认模式 | 被拒绝（应该如此，没有比原来权限高） |
| `--allowedTools Write`，默认模式 | 写成 |

`--model claude-haiku-4-5` 启动的对话，续跑后还是 `claude-haiku-4-5`。

### 你自己结束的对话不再续

用真实交互界面、hook、后台程序和续跑辅助程序一起跑，普通模式，跑在伪控制台上。

| 怎么结束的 | 断网时队列 | 网恢复后 |
|---|---|---|
| `/exit`、关窗口、Ctrl+C、Ctrl+D | `user_ended` | 仍是 `user_ended`，没有启动续跑 |
| `/clear`（窗口还开着） | `user_ended` | 同上 |
| 强杀 | `waiting` | `completed`，续了 1 次，同一对话 |
| `-p` 跑完 | `waiting` | `completed`，续了 1 次，同一对话 |
| 窗口一直开着 | `waiting` | 分叉跑完，窗口还活着；之后关原窗口，队列不变 |

限制：

- 关窗口是关闭伪控制台模拟的，没有真的点 X。
- 终端程序崩溃和关窗口分不开，按不续处理。
- 后台没在跑时，结束事件送不到。后台重启后辅助程序的记录也没了，所以不会续，队列转 `needs_user` 并通知。

### 文件归属

在一台真实机器的几千个对话记录文件上只读跑过：首次全量约 2 分钟，进程内存峰值约 80 MB。抽查了最大的几个对话，能在对话记录里找到对应的命令，文件夹创建时间和大小也对得上。

## 没验证的

- 真实付费会话、Codex、Windows 服务、WFP 防火墙、切 Wi-Fi、电源设置、合盖、拔网线。
- 离开模式下网真的恢复、真的续跑、续跑结束后才退出，没有用真实程序连起来跑过：离开模式打开网络模块会动真实网络，所以是分开验证的。
- 交互界面只在伪控制台上跑过，没在真实窗口里跑过。
- 中途 `/effort` 不带；中途 `/model` 切到带 `[1m]` 的模型时后缀会丢。启动参数名单对应 2.1.309，实测的只有 `--model`、`--allowedTools`。
