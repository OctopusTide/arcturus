# 出口保护行为与边界

2026-11-02 修订。

- 新增或更换路线时先建立保护；已验证的相同路线在复查期间保持现状。原生后端只在策略、VPN LUID 或规则版本变化时原子更新过滤器。
- 出口未知、探测失败、节点身份不可读或尚未配置目标时只请求封网。只有已取得出口证据且目标不匹配时，才执行用户选择的冻结/强杀。
- 显式移出程序或禁用模块会删除本模块的规则；正常停止仍保留临时封网锁供重启复查。某个程序解冻失败不会阻止后面的程序处理。
- 出口错误或未知的临时锁拦截受保护程序所有 IPv4/IPv6 连接和接收授权，包括所有回环地址、任意端口，不再只封配置的代理端点。
- 出口通过检查后，本机代理路线只允许配置的 IP、端口和 TCP；其他地址族、地址、端口、协议仍阻断。需要 MCP/IDE/回调的用户不能假设代理路线放行所有本机服务。VPN 路线在正常状态保留回环，临时锁期间也封回环。
- 管理员端拒绝 UNC、映射网络盘和重解析路径，不以 SYSTEM 身份为远程程序解析 WFP App ID。

## 尚未实现的隔离

WFP 当前按完整可执行文件路径和用户过滤。它不自动继承到任意 git、curl、python 等子进程，临时锁能阻止这些列出的程序再连接任何本机代理，但它不能约束未列入的子进程或另一程序代为转发。状态会提示此边界。可以显式列出所需子工具，但这仍不构成无竞态的进程树隔离。

要保证任意子进程首包都不会绕过，需要另外设计并验收内核进程感知过滤或受控沙箱启动。本次没有添加驱动或扩大为全用户防火墙，也没有声称上述问题已完全解决。

真实 WFP 对存量连接的重授权、本机集成和 VPN 重建仍需在授权安装服务后实测。本轮只验证规则计划、模拟状态机和编译。实现参考 [Microsoft 回环过滤示例](https://learn.microsoft.com/en-us/windows/win32/teredo/implementing-firewall-filters-for-teredo)。

封网失败会明确通知“当前无法确认已封网”，按 1、2、4…60 秒退避重试操作，不必等网络变化，也不为重试反复请求公网。不能在服务拒绝/缺失时声称已保护。服务某一恢复项失败不会拒绝无关的 WFP 操作。本轮按用户要求未安装服务，因此没有实际添加 WFP 过滤器；真实规则生效、已有 TCP/UDP 流重授权仍未验收。已有流若平台未及时重授权，应用级规则无法凭代码检查保证所有旧字节立即停止。
